## 1. Концептуальная Парадигма Системы GTR1

Ядро **GTR1 (Generative-Transformational Robotics 1)** функционирует как нейро-символический процессор, основанный на двух встречных потоках данных:

1. **DTR (Direct Transformation Run — Прямой ход):**
   - Движение информации от низкоуровневых сенсоров (RGB-D камера) к устойчивым семантическим абстракциям (инвариантам).
   - Цепочка: `Сенсор (TUM RGB-D)` $\to$ `Шлюз (SLGW)` $\to$ `Воксельная карта (MP10 / OctoMap)` $\to$ `Нейросеть (CNN1 YOLOv8)` $\to$ `Карта Инвариантов (MP11)`.
   - Задача: кристаллизовать непрерывный поток зашумленных пикселей в дискретные объекты памяти ("стол", "чашка", "мышь") без размножения идентификаторов (UUID).

2. **RTR (Reverse Transformation Run — Обратный ход):**
   - Превращение высокоуровневой потребности агента в физически исполнимый граф действий.
   - Цепочка: `Мотиватор (MTV1)` $\to$ `Предиктор (PRD1 / A*)` $\to$ `Синтаксический валидатор (SPL1)` $\to$ `Моторы / Кинематика (OP13)` $\to$ `Лог Опыта (TRL1)`.
   - Задача: отталкиваясь от цели, рассчитать вектор невязки, проверить свободность лучей, обойти препятствия с запасом безопасности и свести дистанцию к нулю при физическом контакте.

## 2. Подробный Разбор Компонентов `src/core/` (Ядро Памяти и Доменные Модели)

### 2.1. Базовый Класс Валентностей: `vali.hpp`
- **Файл:** [`src/core/include/vali.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/vali.hpp)
- **Назначение:** Реализация концепции валентностей химико-семантического связывания сущностей. Все ключевые доменные объекты наследуют `ValiBase`.
- **Ключевой функционал:**
  - Генерация и строгая валидация UUIDv4 по стандарту RFC 4122.
  - Управление динамическими слотами валентностей: открытие (`open_valence`), закрытие идентификатором целевого объекта (`close_valence`), проверка открытых слотов (`has_open_valences`, `is_valence_open`).
  - Потокобезопасность на уровне каждого экземпляра через `std::shared_mutex` (RW-блокировка).
  - Полная двусторонняя сериализация в Protobuf DTO `gtr1::models::ValiBase`.

### 2.2. Воксельное Пространство: `mp10_space.hpp`
- **Файл:** [`src/core/include/mp10_space.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/mp10_space.hpp)
- **Назначение:** Доменная карта трехмерного геометрического пространства агента.
- **Ключевой функционал:**
  - Инкапсулирует иерархическое октодерево `octomap::OcTree` с разрешением $0.05$ м (5 см).
  - Хранит и обновляет текущую позу агента в виде матрицы $SE(3)$ (`Eigen::Matrix4f`).
  - Метод `raycast(origin, target, hit_point)`: физическое бросание луча в октодереве для определения препятствий. Возвращает `true`, если путь свободен, и точку первого столкновения при коллизии.
  - Метод `is_node_free(pos)`: проверка проходимости конкретной 3D координаты.
  - Метод `is_near_obstacle(pos, margin)`: проверка наличия препятствий в защитном радиусе Safety Margin ($0.3$ м).
  - Метод `get_occupied_voxels()`: выгрузка всех занятых вокселей для 3D визуализации.

  - Фильтрация шумов: отсечение слепой зоны сенсора ($< 0.4$ м) и дальнего рассеяния ($> 4.0$ м).
  - Даунсэмплинг кадра с шагом пикселей для достижения рекордной задержки вокселизации ($0.10$ мс на кадр при пороге $33$ мс).

### 2.4. Доменный Объект Инварианта: `mp11_object.hpp`
- **Файл:** [`src/core/include/mp11_object.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/mp11_object.hpp)
- **Назначение:** Единичный кристаллизованный объект памяти (инвариант среды).
- **Ключевой функционал:**
  - Наследует `ValiBase`.
  - Трехмерный Bounding Box (`Box3D`: центр и размер в метрах).
  - Пространственный якорь (`spatial_anchor` в виде `Eigen::Vector3f`).
  - Семантический вектор признаков CLIP/CNN: `std::array<float, 512>`.
  - Метод `compute_similarity(other)`: вычисление косинусного сходства между 512-мерными векторами по формуле $\frac{\mathbf{a} \cdot \mathbf{b}}{\|\mathbf{a}\| \|\mathbf{b}\|}$.
  - Метод `distance_to(other)`: Евклидово расстояние между центроидами объектов.

### 2.5. Менеджер Карты Инвариантов: `mp11_manager.hpp` / `mp11_manager.cpp`
- **Файлы:** [`src/core/include/mp11_manager.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/mp11_manager.hpp), [`src/core/mp11_manager.cpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/mp11_manager.cpp)
- **Назначение:** Управление коллекцией инвариантов и подавление дубликатов (Deduplication / Invariant Fusion).
- **Ключевой функционал:**
  - Метод `add_or_merge_invariant(new_obj)` реализует каноническое правило слияния:
    $$\text{match}(\text{class}) \quad \mathbf{AND} \quad \text{Distance} < 0.5\,\text{м} \quad \mathbf{AND} \quad \text{CosineSimilarity} > 0.85$$
  - При слиянии: сглаживание шума координат центроида, усреднение и ре-нормализация эмбеддинга, **полное сохранение существующего UUID** (исключение пролиферации идентификаторов).
  - Потокобезопасный доступ (`std::shared_mutex`).
  - Методы запросов: `get_invariant`, `find_by_class`, `get_invariants_count`, `get_domain_invariants`.

### 2.6. Доменный Сплайс: `mp12_oprn.hpp`
- **Файл:** [`src/core/include/mp12_oprn.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/mp12_oprn.hpp)
- **Назначение:** Базовый триплет поведения: `Субъект` $\xrightarrow{\vec{b}} \text{Объект}$.
- **Ключевой функционал:**
  - Имеет ровно 2 валентности: слот 0 (UUID субъекта), слот 1 (UUID объекта-цели).
  - Вектор физического смещения $\vec{b} = \vec{p}_{\text{target}} - \vec{p}_{\text{subject}}$.
  - Строгий конечный автомат состояний (FSM):
    - `PENDING` $\to$ `VALIDATED` (путь чист) или `COLLISION` (препятствие).
    - `VALIDATED` $\to$ `EXECUTED` (моторы отработали) или `COLLISION` (динамическая помеха).
    - `COLLISION` $\to$ `PENDING` (повторный пересчет).
    - `EXECUTED` $\to$ терминальное состояние.
  - Защита от невалидных переходов через исключение `std::logic_error`.

### 2.7. Схема Событий (Поведенческий Граф): `mp13_blom.hpp`
- **Файл:** [`src/core/include/mp13_blom.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/mp13_blom.hpp)
- **Назначение:** Направленный маршрутный граф сплайсов (маршрут решения задачи).
- **Ключевой функционал:**
  - Последовательность UUID сплайсов (`oprn_sequence`).
  - Флаг завершенности цепочки `is_complete`.
  - Дофаминовый маркер исхода (`outcome_marker` в диапазоне $[0.0, 1.0]$) — оценка успешности опыта агента.

### 2.8. Мотиватор Агента: `mtv1_motivator.hpp` / `mtv1_motivator.cpp`
- **Файлы:** [`src/core/include/mtv1_motivator.hpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/include/mtv1_motivator.hpp), [`src/core/mtv1_motivator.cpp`](file:///Ubuntu/home/kirill/gativus/demonstration%20GTR1/src/core/mtv1_motivator.cpp)
- **Назначение:** Инициатор обратного хода (RTR).
- **Ключевой функционал:**
  - Инжекция цели (`inject_goal`): задание класса и координат объекта, уровня срочности `urgency`.
  - Метод `calculate_distance_to_zero(agent_pos)`: непрерывный расчет вектора невязки $\vec{d} = \vec{p}_{\text{target}} - \vec{p}_{\text{agent}}$ и дистанции до обнуления.
  - Метод `is_goal_achieved(agent_pos, threshold)`: проверка физического контакта (по умолчанию $\le 0.2$ м).
  - Метод `zero_goal()`: обнуление цели при физическом контакте и сброс срочности.
