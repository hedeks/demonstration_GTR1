# Спецификация алгоритмов ML и SLAM

## 1. Конфигурация ML-моделей (Блок 6)
- **Модели:** Используем YOLOv8 Nano (`yolov8n.pt`) для генерации Bounding Boxes. Для формирования эмбеддингов (512-d) используем OpenAI CLIP (`ViT-B/32`).
- **3.3 Сериализация эмбеддингов:** Эмбеддинги (Float[512]) сериализуются в Protobuf как упакованный массив `repeated float [packed=true]` для экономии байтов.
- **6.1 Пороги совпадения:** Косинусное сходство (Cosine Similarity) эмбеддингов для слияния объектов в `MP11Manager` должно быть `> 0.85`.
- **6.4 Хранение весов:** Веса моделей вшиты прямо в Docker-образ (`/app/models/`). Конфликты классов разрешаются маппингом ID (ID 0 = "person", ID 41 = "cup").
- **6.2 Метрики качества:** Для детекции требуем порог уверенности `conf = 0.5`. Всё, что ниже, отбрасывается (защита от ложных срабатываний).

## 2. Конфигурация SLAM и Геометрии (Блок 7)
- **7.1 Параметры OctoMap (MP10):** 
  - Разрешение вокселя: `0.05` метра (5 см кубик).
  - Максимальная глубина луча сенсора: `5.0` метров.
  - Вероятностная модель: `prob_hit = 0.7` (быстро запоминает стены), `prob_miss = 0.4` (быстро очищает движущиеся объекты).
- **7.2 Калибровка RGB-D:** Используем фабричную матрицу интринсиков камеры $K$, взятую из метаданных датасета TUM.
- **7.3 Фильтрация и Синхронизация:** Кадры RGB и Depth синхронизируются по таймстемпу с допуском `0.02s`. Выбросы (шум глубины) фильтруются алгоритмом Statistical Outlier Removal (SOR).
- **7.4 Персистентность:** Воксельная база `MP10_Space` сбрасывается на жесткий диск в бинарном формате `.bt` (Binary Tree) при штатном завершении программы.
