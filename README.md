# GTR1 (Гативус Информационно-Сенсомоторный Уровень)

**GTR1 (Gativus Transformation 1)** — фундаментальное ядро интеллектуального автономного агента, реализующее базовый сенсомоторный уровень теории Гативуса. Система строит целенаправленное пространственное поведение: переход от текущего состояния «где агент находится» к целевому состоянию «где находится объект потребности», связывая непрерывное восприятие среды с дискретными схемами действий.

---

## Философско-Архитектурная Парадигма

GTR1 функционирует на основе двух встречных, непрерывно согласованных информационных потоков без единого централизованного диспетчера:

```
                     ┌────────────────────────────────────────┐
                     │          МОТИВАЦИЯ И ПАМЯТЬ            │
                     │       MTV1 (Цель)  ⇄  TRL1 (Опыт)      │
                     └──────────────────┬─────────────────────┘
                                        │  RTR (Обратный ход: Развёртка)
   DTR (Прямой ход: Свёртка)            ▼
   ┌─────────────────────────┐     ┌─────────────────────────┐
   │ MP13: Событийный граф   │ ◄───┤ PRD1: Семантический A*  │
   ├─────────────────────────┤     ├─────────────────────────┤
   │ MP12: Сплайсы OPRN      │ ◄───┤ SPL1: Проверка клиренса │
   ├─────────────────────────┤     ├─────────────────────────┤
   │ MP11: Инварианты (3D)   │ ◄───┤ CNN1: Детектор объектов │
   ├─────────────────────────┤     └────────────┬────────────┘
   │ MP10: Воксельная сетка  │ ◄──┐             │
   └────────────┬────────────┘    │             ▼
                │                 │ ┌─────────────────────────┐
   ┌────────────┴────────────┐    └─┤ OP13: Моторный контур   │
   │ SLGW: Фильтрация датчиков│     └────────────┬────────────┘
   └────────────▲────────────┘                  │
                │                               ▼
   ┌────────────┴─────────────────────────────────────────────┐
   │             ФИЗИЧЕСКИЙ МИР / СИМУЛЯТОР                   │
   │        (RGB-D Сенсоры  ⇄  Колёсное шасси робота)         │
   └──────────────────────────────────────────────────────────┘
```

### 1. DTR (Прямой ход — Свёртка и Узнавание)
Превращает непрерывный сенсорный поток в дискретные инвариантные структуры мира:
* **Сенсорный шлюз (`SLGW`):** Приём RGB-D кадров, двусторонняя билатеральная фильтрация глубины и фильтрация состояния в $SE(3)$ (фильтр Калмана).
* **Пространственная карта (`MP10`):** Построение динамической воксельной сетки занятости (OctoMap) и расчёт локализации шасси.
* **Семантическое зрение (`CNN1` $\to$ `MP11`):** Детекция объектов, проекция 2D-ограничивающих рамок в 3D-пространство и слияние инвариантов по пространственно-семантическому критерию без дублирования UUID при джиттере.

### 2. RTR (Обратный ход — Целеполагание и Развёртка)
Разворачивает принятую цель в непрерывное кинематическое движение:
* **Мотиватор (`MTV1`):** Задаёт физиологический вектор потребности (расстояние до целевого объекта или путевой точки), который агент стремится обнулить ($b \to 0$).
* **Предиктор и Долговременная память (`PRD1` $\leftrightarrow$ `TRL1`):** Поиск ранее успешных траекторий в логе памяти либо построение нового оптимального маршрута через $A^*$ в плоскости пола.
* **Сплайсер (`SPL1`):** Проверка проходимости прямого пути и высотного габаритного цилиндра робота (Clearance Envelope). При обнаружении препятствий сплайсер переводит шаг в `COLLISION`, инициируя перепланирование.
* **Событийные цепочки (`MP12` / `MP13`):** Формирование триплетов OPRN (*Субъект — Движение — Объект*) и их сборка в граф событий BLOM, упорядочивающий локальное субъективное время агента.
* **Моторный исполнитель (`OP13`):** Детерминированная трансляция $b$-векторов в кинематические команды скорости ($v_x, \omega_z$), включая алгоритмы маневрирования и выхода из тупиков/углов.

## Базовые Структуры Данных (Модели RAM)

Все ключевые сущности когнитивного ядра унаследованы от базового класса `VALI_GTR1` и оперируют механизмом открытых/закрытых валентностей:

| Структура | Пространство / Роль | Описание и Представление в памяти |
|---|:---:|---|
| **`MP10_Space`** | База (MP10) | Воксельное представление среды (OctoMap) и 6DoF-поза робота в $SE(3)$. |
| **`MP11_Object`** | Инварианты (MP11) | 3D-центроид, размеры габаритного бокса, метка семантического класса и дескриптор. |
| **`MP12_Oprn`** | Сплайсы (MP12) | Элементарный поведенческий акт (Субъект $\to$ $b$-вектор $\to$ Объект) с FSM-статусами (`PENDING`, `VALIDATED`, `EXECUTED`, `COLLISION`). |
| **`MP13_Blom`** | Схемы событий (MP13) | Направленный граф шагов OPRN, фиксирующий траекторию и итоговый маркер исхода (`outcome_marker`). |
| **`TRL1_Log`** | Память опыта | Хранилище запланированных и успешно завершённых графов BLOM с быстрым извлечением по классу цели. |
| **`MTV1_Goal`** | Потребность | Текущий активный вектор цели, целевой семантический класс и мера срочности. |

## Технологический Стек

Проект спроектирован по модульному принципу и объединяет производительность системного C++ с гибкостью ML-экосистемы Python:

* **Когнитивное Ядро (C++20):** 
  * Алгоритмы $A^*$, структуры `VALI`, менеджеры памяти `TRL1`, сплайсер `SPL1`, фильтры `KalmanFilterSE3` и `DepthFilter`.
  * Библиотеки: **Eigen3**, **OctoMap**, **ZeroMQ (cppzmq)**, **Protocol Buffers**.
* **Служба Машинного Обучения (Python 3.12):**
  * Инференс детекции объектов на базе **Ultralytics YOLOv8** с пространственной обратной проекцией лучей камеры в 3D-координаты.
* **Физическая Симуляция (Python 3.12):**
  * Среда **PyBullet** с замкнутым контуром симуляции (60 FPS), эмуляцией RGB-D камеры, кинематики дифференциального шасси и физических препятствий.
* **Межпроцессное Взаимодействие (IPC):**
  * Неблокирующий обмен сообщениями через **ZeroMQ** и строго типизированные схемы **Protobuf** (`gtr1_structures.proto`, `ipc_messages.proto`).
* **Наблюдаемость и UI:**
  * Асинхронный шлюз **WebSocket Bridge** (`ws_bridge.py`) и веб-дашборд на **Three.js / Vanilla JS** с интерактивной 3D-визуализацией вокселей, графа OPRN и телеметрии в реальном времени.

## Режимы Работы

Система поддерживает два взаимодополняющих режима функционирования:

1. **Режим 3D-Симуляции (`--sim`):**
   * Запуск виртуального робота в физической арене PyBullet.
   * Активное автономное исследование пространства, динамический объезд препятствий и сближение с целевыми предметами в замкнутом цикле управления.
2. **Режим Воспроизведения Датасетов (`--dataset`):**
   * Детерминированное офлайн-воспроизведение синхронизированных RGB-D потоков (например, TUM RGB-D `freiburg1_desk`).
   * Используется для регрессионного тестирования, валидации фильтров и калибровки одометрии.

## Сборка и Быстрый Старт

### Системные требования
* **ОС:** Linux (Ubuntu 22.04 / 24.04 LTS или WSL2)
* **Компилятор:** GCC $\ge 11$ или Clang $\ge 14$ с поддержкой C++20
* **Инструменты:** CMake $\ge 3.20$, Protobuf Compiler (`protoc`), Python $\ge 3.10$

### 1. Автоматический запуск (Рекомендуемый)
Скрипт `run_demo.sh` автоматически компилирует C++ ядро, генерирует Protobuf-биндинги, поднимает сервисы стека (ML, WebSocket, PyBullet, HTTP) и запускает демонстрацию:

```bash
# Запуск полной симуляции с Three.js дашбордом (headless физика)
./run_demo.sh

# Запуск симуляции с графическим окном PyBullet GUI
./run_demo.sh --gui

# Запуск воспроизведения эталонного датасета TUM RGB-D
./run_demo.sh --dataset
```
После запуска веб-интерфейс дашборда доступен по адресу: **`http://localhost:8000`**.

### 2. Ручная сборка и тестирование C++ ядра
```bash
# Генерация Protobuf для Python
protoc -I=02_data_models -I=04_interfaces --python_out=src/ml_service \
       02_data_models/gtr1_structures.proto 04_interfaces/ipc_messages.proto

# Сборка Release-бинарников
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j4

# Запуск полного набора автоматизированных тестов (58 тестов)
ctest --output-on-failure
```
