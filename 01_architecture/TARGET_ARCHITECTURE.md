## 1. Введение и Архитектурное Видение

Когнитивная архитектура **GTR1** объединяет методы глубокого машинного обучения (компьютерное зрение, авторегрессионные политики) со строгой символической логикой и пространственной памятью (**Neuro-Symbolic Cognitive AI**).

В отличие от чистого сквозного обучения с подкреплением (End-to-End RL), где робот управляется «черным ящиком» без гарантий безопасности, и в отличие от классических дискретных планировщиков ($A^*$/Dijkstra), подверженных замираниям на стыках сетки, GTR1 реализует **двухуровневую иерархию управления с детерминированным символическим щитом**.

## 2. Компонентная Модель и Потоки Данных (PlantUML)

Архитектурная схема фиксирует разделение системы на 6 функциональных доменов:

![Компонентная архитектура](target_cognitive_architecture.png)

Исходный код схемы: [`01_architecture/target_cognitive_architecture.puml`](target_cognitive_architecture.puml)

### Описание функциональных доменов:

1. **Perception & World State (Прямой ход DTR):**
   * **`Sensor Stream`:** Физический мир (симулятор PyBullet или реальная RGB-D камера) функционирует в **независимом реальном астрономическом времени**. Камера генерирует кадры строго из физического положения $T_{cam}$ на момент съемки.
   * **`SLGW (Sensor Linker Gateway)`:** Осуществляет фильтрацию сенсорных шумов (Kalman SE3 на позе + билатеральная фильтрация карты глубин) и выполняет вокселизацию в `MP10Space` (OctoMap).
   * **`CNN1 + CLIP Service`:** Выполняет детекцию объектов (YOLOv8) и извлечение 512-мерных семантических векторов CLIP на GPU (**NVIDIA CUDA FP16**), передавая результаты в `MP11Manager`.

2. **Motivation & Needs (`MTV1`):**
   * Формирует целевую невязку агента: класс объекта (`"cup"`) или интерактивную путевую точку с дашборда.
   * Инициирует обратный ход **RTR (Retro-Time Reasoning)**.

3. **Macro-Level Reasoning — Стратегический разум (`PRD1`, ISSUE-10):**
   * Функционирует по принципу **Action Tokenization & Function Calling** (аналог трансформера).
   * Предсказывает не сантиметры траектории, а **последовательность токенов действий OPRN** (цепочку `BLOM`): $\langle \text{Subject}, \vec{b}\text{-vector}, \text{Target} \rangle$.
   * Опирается на эпизодическую память успешного опыта `TRL1Log` (`outcome_marker >= 0.85`).

4. **Micro-Level Kinematics — Моторный мозжечок (`SPL1`, ISSUE-11):**
   * Работает с высокой частотой ($30\text{--}60\text{ Гц}$) в локальном контуре физики.
   * Принимает активный токен OPRN и локальный срез вокселей ($1.5\text{м}$ вокруг шасси).
   * Предсказывает непрерывные приращения скоростей $(\Delta v_x, \Delta w_z)$ для плавного движения по дугам, отслеживает прогресс выполнения OPRN (`progress`) и выполняет локальный эластичный изгиб вектора (**Elastic Warping**) для обхода ножек мебели без глобального перепланирования.

5. **Deterministic Safety Shield (Символический щит):**
   * Математический барьер: ни одна команда не поступает на приводы шасси без лучевой проверки (`raycast`) в OctoMap с учетом габаритного цилиндра робота (Clearance Envelope).
   * Предотвращает столкновения при любых галлюцинациях нейросетевых моделей.

6. **Synchronous Telemetry (`TICK_BUNDLE`, ISSUE-09):**
   * Атомарный пакет тика связывает номер кадра `frame_id`, позу $SE(3)$, срез карты занятости (прореженный до 5 тиков), сплайн OPRN и статус цели.
   * В браузере Three.js сцена обновляется синхронно в рамках одного кадра `requestAnimationFrame` с **0 мс лагом**.

## 3. Тактовый Когнитивный Цикл (Sequence Diagram)

Последовательность взаимодействия компонентов на каждом шаге времени представлена на диаграмме:

![Когнитивный цикл](cognitive_cycle_sequence.png)

Исходный код схемы: [`01_architecture/cognitive_cycle_sequence.puml`](cognitive_cycle_sequence.puml)

### Временные бюджеты такта (Frame Budget @ 30 FPS = 33.3 мс):
* **Рендеринг / Захват кадра (GPU):** $\sim 2\text{ мс}$
* **Фильтрация глубины + Вокселизация OctoMap (C++):** $\sim 6\text{ мс}$
* **ML Инференс CNN1 (YOLO + CLIP на CUDA FP16):** $\sim 8\text{ мс}$ (в фоновом параллельном потоке)
* **Микро-сплайсинг SPL1 + Проверка щита безопасности:** $\sim 1.5\text{ мс}$
* **Сериализация и отправка TICK_BUNDLE:** $\sim 0.5\text{ мс}$
* **Итоговый запас по времени:** $> 15\text{ мс}$ свободного ресурса CPU/GPU.

## 4. Сравнительная Таблица: Было (MVP Baseline) vs Стало (Target Architecture)

| Аспект | Было (Стартовый MVP) | Стало (Целевая Когнитивная Архитектура) |
| :--- | :--- | :--- |
| **Планирование пути** | Дискретный $A^*$ по 3D-сетке; замирает при недостижимости стола | **PRD1 Action-Token Transformer:** авторегрессионная генерация токенов действий OPRN |
| **Управление моторами** | Захардкоженные эвристики в `main.cpp`; разворот на месте с $v_x=0$ | **SPL1 Dynamic Splicer:** плавное управление по дугам с адаптацией к инерции |
| **Локальные препятствия** | Любая помеха бракует сплайс $\to$ сброс и долгий пересчет $A^*$ | **Elastic Splice Warping:** локальный дуговой обход без вызова макро-планировщика |
| **Зрение и семантика** | 80 фиксированных классов COCO | **Open-Vocabulary CLIP:** поиск любых объектов по произвольному текстовому описанию |
| **Безопасность** | Эвристические штрафы в стоимости пути | **Детерминированный символический щит:** физический барьер raycast перед моторами |
| **Телеметрия в UI** | Асинхронные разрозненные топики с визуальным лагом карты и позы | **Атомарный TICK_BUNDLE:** строгая покадровая синхронизация (0 мс джиттер) |
